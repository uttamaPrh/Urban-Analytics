  Version: 1.0

  1) EXECUTIVE SUMMARY

  Urban Analytics Platform is a full-stack geospatial analytics system that visualizes country-level indicators on a 3D globe and dashboard. It combines REST Countries v5 country metadata, World Bank WDI, UK Police for GB sampling, Overpass, OpenAQ, and includes an ML-based forecasting module for population and GDP per capita.

  Primary user flow:
  1. User opens app and sees globe.
  2. User selects country.
  3. Dashboard loads KPIs/charts across tabs.
  4. Predictions tab requests backend ML forecasts.
  5. If backend is unavailable, frontend shows explicit fallback forecast state.

  2) SYSTEM GOALS

  - Provide globally scoped country analytics with chart-first presentation.
  - Keep forecast logic transparent and auditable for dissertation/research use.
  - Handle sparse WDI data robustly (missing indicators, missing years, unstable upstream API).
  - Maintain modular architecture so frontend UI and prediction logic evolve independently.

  3) HIGH-LEVEL ARCHITECTURE

  Frontend:
  - React 18 + TypeScript + Vite + TailwindCSS
  - Zustand for UI/app state
  - TanStack React Query for data fetching/caching
  - Recharts for analytics and forecast visuals
  - Globe.gl + MapLibre + Deck.gl for geospatial interaction

  Backend:
  - FastAPI (Python)
  - pandas/numpy for preprocessing
  - scikit-learn for ML models and evaluation
  - requests for World Bank API access and REST Countries v5 backend proxying
  - Uvicorn runtime

  Design principle:
  - Backend ML is authoritative for forecasts.
  - Frontend fallback exists only for continuity when backend fails.

  7) PREDICTION PIPELINE (BACKEND AUTHORITATIVE FLOW)

  Step 1: Fetch WDI per indicator/year for selected ISO3 country.
  Step 2: Build yearly panel dataset by merging target + features.
  Step 3: Validate target coverage (minimum usable target points required).
  Step 4: Missing-data handling:
  - Drop indicators with excessive missingness.
  - Drop years with excessive row missingness.
  - Apply limited forward/backward fill where defensible.
  Step 5: Time-ordered split (no random split for time series).
  Step 6: Train baseline Linear Regression and main Random Forest Regressor.
  Step 7: Evaluate on recent holdout with MAE, RMSE, R2.
  Step 8: Select model with lower holdout RMSE.
  Step 9: Estimate future feature values via trend extrapolation.
  Step 10: Forecast next 5 years; emit warnings/coverage details.
  Step 11: Cache result to reduce repeated upstream calls and latency.

  8) MODELING DETAILS AND FORMULAS

  8.1 Linear Regression
  y = beta0 + beta1*x1 + ... + betan*xn

  8.2 Random Forest Regressor
  y_hat = (1 / T) * SUM(tree_i(x)) for i in 1..T

  8.3 Growth Percentage
  growth% = ((predicted_5y - latest_actual) / latest_actual) * 100

  8.4 MAE
  MAE = (1/n) * SUM(|y - y_hat|)

  8.5 RMSE
  RMSE = SQRT((1/n) * SUM((y - y_hat)^2))

  8.6 R2
  R2 = 1 - (SS_res / SS_tot)

  8.7 Model selection rule
  best_model = argmin(holdout_RMSE)

  8.8 Fallback model conditions
  If feature/row coverage is too weak for reliable ML, fallback trend logic is allowed with explicit warning flags.

  9) BACKEND API CONTRACT

  Base URL (dev):
  - http://127.0.0.1:8001

  Endpoints:
  - GET /health
  - GET /country/{countryCode}
  - GET /predict/population/{countryCode}
  - GET /predict/gdp/{countryCode}
  - GET /predict/all/{countryCode}

  Expected prediction payload fields:
  - countryCode
  - datasetName ("World Development Indicators (WDI)")
  - provider ("World Bank Open Data")
  - targetIndicator
  - modelUsed
  - featuresUsed
  - featuresDropped
  - warnings
  - historicalData
  - forecastData
  - latestActualValue
  - predictedValueIn5Years
  - growthPercentage
  - mae
  - rmse
  - r2
  - trainingYearsUsed
  - dataCoverageSummary

  Error semantics:
  - 422 when target coverage is too low to train/evaluate
  - 502 for upstream World Bank/API transport failures
  - 503 when REST_COUNTRIES_API_KEY is missing for /country
  - 404 for invalid route

  10) FRONTEND BEHAVIORAL CONTRACT (PREDICTIONS TAB)

  Loading state:
  - Show clear ML loading status.

  Success state:
  - Render two charts (population and GDP per capita) with clear actual vs forecast separation.
  - Render KPI cards and evaluation metrics.
  - Render used/dropped features and warnings.

  Fallback state:
  - Display explicit message that backend is unavailable and browser fallback is in use.

  Error state:
  - Render concise actionable error content (status + reason where available).

  No-data state:
  - Show empty-state guidance when neither backend nor fallback can produce forecast.

  11) RUNTIME AND SCRIPTS

  Prerequisites:
  - Node.js >= 18
  - npm
  - Python >= 3.11
  - Internet access
  - REST_COUNTRIES_API_KEY in .env.local for country profile metadata

  Install:
  - npm install
  - python -m pip install -r backend/requirements.txt
  - get a REST Countries v5 API key from https://restcountries.com/
  - create/sign in to the REST Countries account or dashboard and generate/copy a v5 key
  - copy .env.example to .env.local and set REST_COUNTRIES_API_KEY

  Run:
  - npm run dev        (frontend + backend)
  - npm run frontend   (frontend only, default 5173)
  - npm run backend    (backend only, default 8001)

  Verification commands:
  - npm run typecheck
  - npm run build
  - GET http://127.0.0.1:8001/health
  - GET http://127.0.0.1:8001/country/CAN

  12) KNOWN FAILURE MODES AND OPERATIONAL TROUBLESHOOTING

  1. ERR_CONNECTION_REFUSED
  - Cause: backend not running or wrong port
  - Action: start backend, verify /health on 8001

  2. WinError 10013 / Errno 10048
  - Cause: port bind blocked/already in use
  - Action: stop old process, reuse configured 8001

  3. {"detail":"Not Found"}
  - Cause: incorrect route
  - Action: use documented endpoints exactly

  4. {"detail":"Not enough WDI target data ..."}
  - Cause: sparse target series for selected country/indicator
  - Action: switch country or rely on explicit fallback behavior

  5. 502 / SSL EOF / upstream instability
  - Cause: transient World Bank/API transport failures
  - Action: retry later; backend already applies retry/fallback URL strategy

  6. REST Countries v5 profile unavailable
  - Cause: missing/expired REST_COUNTRIES_API_KEY or upstream REST Countries failure
  - Action: confirm .env.local, restart npm run dev, test /country/CAN
  - Impact: country profile may be null, but World Bank data can still load

  7. World Bank indicator deleted/archived
  - Cause: World Bank removed or archived an indicator code
  - Action: replace the affected indicator with a currently available WDI code

  13) NON-FUNCTIONAL REQUIREMENTS

  - UI consistency: dark dashboard theme across tabs.
  - Deterministic, typed data handling in TypeScript interfaces.
  - Separation of concerns:
    - backend/app.py owns ML pipeline
    - frontend renders and explains outputs
  - Private REST Countries credentials stay in ignored .env.local and are never sent to frontend code.
  - Public API volatility is expected and handled defensively.

  14) LIMITATIONS (FOR PROPOSAL HONESTY)

  - Forecast quality is constrained by WDI completeness and reporting lag (latest available years are often ~2023/2024 depending on indicator/country).
  - Random Forest cannot anticipate external structural shocks without exogenous forward features.
  - Future feature extrapolation introduces uncertainty beyond short horizons.
  - Country-to-country data coverage heterogeneity can cause uneven model reliability.

  15) RECOMMENDED ACCEPTANCE CRITERIA

  Minimum technical acceptance:
  1. All existing tabs continue to work without regression.
  2. Predictions tab renders population + GDP 5-year forecasts.
  3. Backend model output includes MAE/RMSE/R2 and feature diagnostics.
  4. Missing-data warnings are visible and understandable.
  5. Backend unavailability yields controlled fallback state, not crash loops.
  6. README and this file accurately match runnable scripts and ports.

  16) PROPOSAL-GENERATION NOTES FOR ANOTHER AI

  If this file is used to create a proposal/specification, the proposing AI should:
  1. Treat backend ML as primary forecast source and frontend trend model as continuity fallback.
  2. Preserve the defined API contract and error semantics.
  3. Preserve time-ordered evaluation methodology (no random split claims).
  4. Include explicit data-quality and coverage-risk statements.
  5. Keep forecast horizon at 5 years unless scope expansion is approved.
  6. Avoid promising policy-shock robustness without additional datasets/features.
  7. Include deployment/ops plan for API instability handling and retries.
