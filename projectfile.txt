URBAN ANALYTICS PLATFORM - PROJECT REPORT

1. PROJECT TITLE

Urban Analytics Platform


2. PROJECT OVERVIEW

Urban Analytics Platform is a web-based geospatial analytics application that allows users to explore country-level urban indicators through an interactive globe and dashboard interface. The application lets a user select a country from a 3D globe and then view demographic, economic, urbanization, and safety-related analytics for that country.

The platform is designed to combine public geographic data, country statistics, World Bank indicators, traffic and road data, air quality data, and crime or safety indicators into one interactive urban analytics experience.


3. OBJECTIVE OF THE PROJECT

The main objective of the project is to provide an interactive and visual analytics dashboard for understanding urban and country-level conditions across the world.

The project aims to:

- Display countries on an interactive 3D globe.
- Allow users to select a country and view analytics.
- Show population, area, density, capital, and regional information.
- Show population and urbanization trends using charts.
- Show economic indicators such as GDP per capita.
- Forecast future population and GDP per capita using a FastAPI machine learning backend with World Bank WDI indicators.
- Show safety indicators globally using World Bank data.
- Show sampled UK Police street incident data for Great Britain when available.
- Present analytics in a clean, modern, dark-themed dashboard.
- Use free public APIs without requiring user authentication.

5. MAIN FEATURES

5.1 Interactive 3D Globe

The application starts with an interactive 3D globe. Users can rotate the globe and select countries. Once a country is selected, the application opens the analytics dashboard for that country.

5.2 Country Analytics Dashboard

After selecting a country, the dashboard displays a country-specific analytics view. The dashboard includes KPI cards, charts, and tab-based sections.

Dashboard tabs include:
- Overview
- Population
- Economy
- Crime and Safety
- Predictions

5.3 Population Analytics

The platform shows population-related information such as:
- Total population
- Population trend
- Area
- Population density
- Capital city
- Region and subregion

Population data is fetched from REST Countries and World Bank APIs.

5.4 Urbanization Analytics

The application includes urbanization analytics, including:
- Urban population share
- Urbanization trend over time

This helps users understand how urbanized a selected country is.

5.5 Economy Analytics

The economy section includes GDP per capita analytics. It displays:
- Latest GDP per capita value
- Historical GDP per capita chart

This gives basic economic context for the selected country.

5.6 Crime and Safety Analytics

The crime and safety section uses a global data approach.

For most countries:
- Safety indicators are fetched from the World Bank.
- Indicators include intentional homicide rate and business losses from crime where available.
- Charts are used to show safety trends.

For Great Britain:
- The app also fetches sampled UK Police street crime incidents when available.
- Local incident categories are displayed when incident data exists.

This design avoids limiting the entire crime feature to UK-only data.

5.7 Charts and Visual Analytics

The dashboard uses Recharts to display:
- Population trend charts
- Urbanization trend charts
- GDP per capita charts
- Global homicide rate charts
- Business crime impact charts
- Safety indicator bars

The charts make the analytics easier to understand than plain text values.

5.8 Responsive Dark-Themed UI

The interface uses a dark theme with styled cards, tabs, spacing, and chart panels. TailwindCSS is used for layout and styling.

5.9 Predictions Analytics

The Predictions tab forecasts:
- Population growth for the next 5 years.
- GDP per capita growth for the next 5 years.

The prediction feature uses the World Bank World Development Indicators dataset. A FastAPI backend fetches WDI indicators, merges them by year, handles missing values, trains machine learning models, evaluates them, and returns forecasts to the React dashboard.

The prediction logic is separated from the UI:
- backend/app.py contains the WDI data fetching, cleaning, model training, model comparison, and API endpoints.
- src/lib/prediction.ts contains the browser fallback forecasting functions.
- src/types/prediction.ts contains TypeScript types for prediction data and backend responses.
- src/components/Sidebar/PredictionsTab.tsx contains the dashboard UI for charts, KPI cards, and model evaluation.

The Predictions tab shows:
- Latest actual population.
- Predicted population in 5 years.
- Latest actual GDP per capita.
- Predicted GDP per capita in 5 years.
- Five-year growth percentage.
- Model used.
- MAE for model evaluation.
- RMSE for model evaluation.
- R2 score for model evaluation.
- Number of years used for training.
- Features used by the model.
- Features dropped because of missing data.
- Missing data warnings.

The prediction charts use Recharts and separate actual historical values from forecast values using different line styles.
The backend responses are cached to reduce repeated API pressure when switching tabs or revisiting the same country.

8. APPLICATION WORKFLOW

1. The user opens the application in the browser.
2. The app displays the interactive 3D globe.
3. The user selects a country.
4. The selected country is saved in the Zustand store.
5. The analytics dashboard opens for the selected country.
6. React Query hooks fetch country-specific data from public APIs.
7. The dashboard displays KPI cards, charts, and safety analytics.
8. The user can switch between dashboard tabs.
9. The user can return to the globe and select another country.


9. STATE MANAGEMENT

Zustand is used for global state management.

The app stores:
- Selected country
- Active analytics tab
- Current map bounding box

This keeps country selection and dashboard state simple and centralized.


10. DATA FETCHING APPROACH

TanStack React Query is used for API data fetching. It provides:
- Query caching
- Loading states
- Error states
- Refetch support
- Reduced duplicate API calls

For Predictions:
- Backend ML endpoint is the primary source.
- Browser forecast is a fallback only when backend is unavailable.
- Automatic retry loops were reduced to avoid repeated noisy failures when backend is down.

Each analytics area has its own hook. This keeps API logic separate from UI components.


11. CHARTING APPROACH

Recharts is used for dashboard charts. The application transforms API time series into chart-friendly arrays containing year and value fields.

The dashboard uses:
- Area charts for population and homicide trends.
- Line charts for urbanization trends.
- Bar charts for population and business crime impact.
- Visual indicator bars for latest safety values.
- Forecast line charts for population and GDP per capita predictions.


12. PREDICTION MODEL AND FORMULAS

The project now uses a FastAPI machine learning backend for the main prediction workflow. The backend uses World Bank WDI indicators and compares a baseline Linear Regression model against a Random Forest Regressor.

Candidate models:
- Linear Regression baseline.
- Random Forest Regressor.
- Log-linear trend fallback when WDI data quality is too weak for ML.

The backend uses time-ordered training and testing. It does not use a random split because the data is a time series. The most recent years are used as the holdout period for model comparison.

12.1 Linear Regression Baseline

Linear Regression is used as the baseline model. It estimates a linear relationship between WDI input features and the target variable.

y = beta0 + beta1*x1 + beta2*x2 + ... + betan*xn

Where:
- y is the target value.
- beta0 is the intercept.
- beta1 to betan are learned coefficients.
- x1 to xn are WDI input features.

12.2 Random Forest Regressor

Random Forest Regressor is the main ML model. It trains many decision trees and averages their predictions.

Prediction formula structure:

y_hat = (1 / T) * sum(tree_i(x))

Where:
- T is the number of trees.
- tree_i(x) is the prediction from one decision tree.
- y_hat is the final averaged prediction.

Random Forest is useful because it can model nonlinear relationships between indicators such as life expectancy, fertility, urbanization, GDP growth, internet use, and trade.

12.3 Future Feature Estimation

Future WDI feature values are not available. The backend estimates future feature values using simple trend extrapolation from historical feature values.

futureFeatureValue = trendModel.predict(futureYear)

These estimated future features are passed into the selected ML model to generate population and GDP per capita forecasts.

12.4 Log-Linear Fallback

If too few rows or too few ML features are available, the backend falls back to a log-linear trend model:

ln(y) = mx + b

The forecast is converted back to the original scale:

y = exp(mx + b)

12.5 Data Cleaning and Missing Value Handling

The backend prepares WDI data by:
- Removing null values.
- Removing invalid years.
- Removing invalid numeric values.
- Merging indicators by year.
- Dropping indicators with too much missing data.
- Dropping years with too many missing feature values.
- Using limited forward-fill and backward-fill for short gaps.
- Continuing with available optional features where possible.
- Returning warnings for missing or dropped indicators.

12.6 Forecast Generation

The backend forecasts 5 years after the latest available WDI year:

futureYear = latestYear + i

Where i ranges from 1 to 5.

Then:

forecastValue = selectedModel.predict(futureYear)

12.7 Growth Percentage Formula

The five-year growth percentage is calculated as:

growthPercentage = ((predictedValueInFiveYears - latestActualValue) / latestActualValue) * 100

This formula is used for both population growth and GDP per capita growth.

12.8 MAE Formula

Mean Absolute Error measures the average absolute error between actual values and fitted model values:

MAE = sum(abs(actualValue - predictedValue)) / n

Lower MAE means the model predictions are closer to the historical values.

12.9 RMSE Formula

Root Mean Squared Error measures the square root of the average squared error:

RMSE = sqrt(sum((actualValue - predictedValue)^2) / n)

RMSE penalizes larger errors more strongly than MAE.

12.10 R2 Formula

R2 measures how much variance in the target is explained by the model:

R2 = 1 - (sum((actualValue - predictedValue)^2) / sum((actualValue - meanActualValue)^2))

12.11 Model Selection Formula

Linear Regression and Random Forest are evaluated on recent holdout years. The selected model is:

bestModel = model with minimum holdout RMSE

This helps avoid a model that looks good across all old historical data but performs poorly on the most recent years.

12.12 Missing Data Handling

The prediction feature safely handles missing or incomplete data. If fewer than two valid data points are available, the app does not train a model and shows an unavailable state instead of crashing.

13. SECURITY AND PRIVACY

The application does not require user accounts, passwords, or private API keys. All data is fetched from public APIs. No personal user data is stored by the application.


14. LIMITATIONS

- Some countries may not have complete World Bank safety or economic data.
- Some countries may not have enough valid World Bank population or GDP data for forecasting.
- The browser-based model is still simpler than backend-trained Random Forest, XGBoost, Prophet, LSTM, or Transformer models.
- The model cannot fully capture sudden shocks, policy changes, wars, pandemics, or complex nonlinear demographic and economic changes without extra explanatory variables.
- UK Police local incident data is only available for Great Britain through the UK Police API.
- Public APIs may rate limit, fail, or return incomplete data.
- The application depends on internet access for live API data.
- Large visualization libraries increase bundle size.

16.1 Troubleshooting Guide

Issue: ERR_CONNECTION_REFUSED in browser network tab
- Cause: backend is not running or wrong backend port.
- Fix: run npm run backend and verify http://127.0.0.1:8001/health.

Issue: WinError 10013 / Errno 10048 while starting backend
- Cause: port conflict or restricted binding.
- Fix: stop previous backend process and restart backend on port 8001.

Issue: {"detail":"Not Found"}
- Cause: wrong backend route.
- Fix: use /health, /predict/population/{ISO3}, /predict/gdp/{ISO3}, or /predict/all/{ISO3}.

Issue: {"detail":"Not enough WDI target data ..."}
- Cause: insufficient historical target data for the requested country.
- Fix: use a country with stronger WDI coverage; frontend fallback may still render an estimated forecast.

Issue: 502 / SSL upstream failures from World Bank
- Cause: temporary World Bank API/network instability.
- Fix: wait and retry; backend already includes retry behavior and endpoint fallback.

18. CONCLUSION

Urban Analytics Platform is a modern full-stack application for exploring global urban indicators through an interactive globe and analytics dashboard. It combines multiple public data sources and presents them using charts, KPI cards, country-specific dashboard sections, and machine learning forecasts.

The project demonstrates frontend development, backend API development, geospatial visualization, API integration, state management, data transformation, chart-based analytics, missing data handling, and machine learning prediction modelling in a single application.
